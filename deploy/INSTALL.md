# Stratum AI — Installation Guide

This guide walks through installing your Stratum AI instance on your own
server. The whole install is one command; everything else here is reference
material for when you need it.

## Prerequisites

- **A server** running a recent Ubuntu-like Linux distribution, reachable on
  the public internet, with at least 4 GB RAM and 2 vCPUs.
- **Docker Engine with the Compose plugin.** If it's not already installed:
  ```bash
  curl -fsSL https://get.docker.com | sh
  ```
  (See <https://docs.docker.com/engine/install/> for other install methods.)
- **A domain name** for your instance (e.g. `app.yourcompany.com`), with a
  DNS **A record** pointing at your server's public IP address. This must be
  in place *before* you run the installer — certificate issuance fails
  otherwise (see Troubleshooting below).
- **Ports 80 and 443 open** to the internet on this server (firewall / cloud
  security group). Stratum AI uses these for HTTPS and for automatic
  certificate issuance via Let's Encrypt — no other inbound ports are
  required.
- **Registry credentials**, if your vendor's image registry is private. The
  installer will offer to run `docker login` for you.

## Quick Start

```bash
# 1. Download and extract the installer kit (your vendor will provide a link)
tar xzf stratum-deploy-kit.tar.gz && cd deploy

# 2. Run the installer
./install.sh

# 3. Open https://<your-domain>, log in with the admin email/password
#    printed at the end of step 2, and complete the setup wizard.
```

That's it. `install.sh` prompts for everything it needs (domain, admin
email, registry) and generates every password and secret key on its own — you
never have to invent or type them.

Prefer no prompts? Run it non-interactively:

```bash
./install.sh --domain app.yourcompany.com \
             --email owner@yourcompany.com \
             --registry ghcr.io/your-vendor \
             --non-interactive
```

## What the installer does

`install.sh`:

1. Checks that Docker and the Compose plugin are installed, warns if ports
   80/443 look busy, and checks it can talk to the Docker daemon.
2. Prompts for your domain, admin email, admin password (or generates one),
   and registry — writing everything into a `.env` file next to
   `docker-compose.client.yml`. Re-running `install.sh` reuses this `.env`
   instead of asking again, unless you pass `--force`.
3. Generates every secret (session signing key, JWT key, PII encryption
   key, database password, Redis password, WhatsApp webhook token) with
   `openssl rand`. Nothing is hardcoded and nothing is shared between
   clients.
4. Pulls the prebuilt application images (`docker compose pull`) and starts
   the stack (`docker compose up -d`): PostgreSQL, Redis, the API, a
   background worker, a task scheduler, the web frontend, and Caddy (which
   handles HTTPS automatically).
5. Waits for the app to report healthy at `https://<your-domain>/health`,
   then prints a summary box with your URL, admin email, and (if one was
   generated) your admin password — shown once, and also saved to
   `.installer-secrets/superadmin-password.txt` so you don't lose it.

Nothing about your business — ad accounts, credentials, branding — is
configured during install. That all happens after you log in (see below).

## What you do after install

1. Log in at `https://<your-domain>` with your admin email and password.
2. Complete the one-time setup wizard.
3. Go to **Settings → Integrations** and connect your ad platform accounts
   (Meta, Google Ads, TikTok, Snapchat) and anything else you use. This is
   done entirely in the browser — you never need server access, and you
   never need to touch a `.env` file, to connect a platform account.

## Configuration reference

All configuration lives in `.env` next to `docker-compose.client.yml`.
Everything marked **auto** below is generated by `install.sh` and normally
never needs to be touched by hand.

| Variable | Auto-generated? | Purpose |
|---|---|---|
| `STRATUM_REGISTRY` | prompted | Image registry images are pulled from |
| `STRATUM_VERSION` | prompted (default `latest`) | Image tag to run |
| `STRATUM_DOMAIN` | prompted | Your instance's public domain |
| `FRONTEND_URL` | derived from domain | Public app URL (`https://<domain>`) |
| `CORS_ORIGINS` | derived from domain | Origins allowed to call the API |
| `OAUTH_REDIRECT_BASE_URL` | derived from domain | Base URL for ad-platform OAuth callbacks |
| `APP_ENV` | fixed: `production` | Application mode |
| `DEBUG` | fixed: `false` | Debug mode (always off in production) |
| `USE_MOCK_AD_DATA` | fixed: `false` | Real ad-platform data, not sample data |
| `SECRET_KEY` | **auto** | Application signing key |
| `JWT_SECRET_KEY` | **auto** | Login token signing key |
| `PII_ENCRYPTION_KEY` | **auto** | Encrypts personal data at rest |
| `POSTGRES_USER` | fixed: `stratum` | Database user |
| `POSTGRES_PASSWORD` | **auto** | Database password |
| `POSTGRES_DB` | fixed: `stratum_ai` | Database name |
| `REDIS_PASSWORD` | **auto** | Cache / task queue password |
| `SUPERADMIN_EMAIL` | prompted | Your admin login email |
| `SUPERADMIN_PASSWORD` | **auto** (or prompted) | Your admin login password |
| `SUPERADMIN_NAME` | default: "Platform Owner" | Display name for the admin account |
| `SMTP_HOST` / `SMTP_PORT` / `SMTP_USER` / `SMTP_PASSWORD` | prompted (optional) | Outbound email for password resets, invites, reports |
| `EMAIL_FROM_NAME` / `EMAIL_FROM_ADDRESS` | default | "From" identity on outbound email |
| `WHATSAPP_VERIFY_TOKEN` | **auto** | Secures WhatsApp webhook callbacks |
| `LOG_LEVEL` / `LOG_FORMAT` | default | Application logging verbosity/format |
| `SENTRY_DSN` | optional | Error tracking, if you use Sentry |
| `ENABLE_METRICS` / `METRICS_API_KEY` | optional | Prometheus-style `/metrics` endpoint |
| `ML_PROVIDER` / `ML_AUTO_TRAIN` / `MARKET_INTEL_PROVIDER` / `SERPAPI_KEY` | default | Intelligence engine configuration |
| `META_*` / `GOOGLE_ADS_*` / `TIKTOK_*` / `SNAPCHAT_*` | leave blank | Ad platform credentials — configure these in-app under Settings → Integrations instead |
| `WHATSAPP_PHONE_NUMBER_ID` / `WHATSAPP_ACCESS_TOKEN` / `WHATSAPP_BUSINESS_ACCOUNT_ID` / `WHATSAPP_APP_SECRET` | leave blank unless using WhatsApp | WhatsApp Business API credentials |

The full, commented list of every variable ships in `.env.client.example`.

## Day-2 operations

**Upgrade to the latest version:**
```bash
./install.sh --upgrade
```
This pulls new images and restarts the stack. Your `.env` and data are left
untouched — no prompts, no secret regeneration.

**View logs:**
```bash
docker compose -f docker-compose.client.yml logs -f          # everything
docker compose -f docker-compose.client.yml logs -f api      # just the API
```

**Back up the database:**
```bash
docker compose -f docker-compose.client.yml exec db \
  pg_dump -U stratum stratum_ai | gzip > stratum-backup-$(date +%F).sql.gz
```

**Volumes to include in your backup strategy:**
- `postgres_data` — the database (the backup command above covers this)
- `asset_uploads` — uploaded creative assets
- `caddy_data` — your TLS certificate (regenerable, but backing it up avoids
  re-requesting from Let's Encrypt)

List them with: `docker volume ls | grep deploy`

**Restart a single service:**
```bash
docker compose -f docker-compose.client.yml restart api
```

## Troubleshooting

**Certificate issuance fails / site shows "not secure".**
Caddy can only get a Let's Encrypt certificate once your domain's DNS A
record resolves to this server *and* ports 80/443 are reachable from the
internet. Confirm with `dig +short your-domain.com` from another machine,
and check Caddy's logs:
```bash
docker compose -f docker-compose.client.yml logs caddy
```
DNS changes can take anywhere from a few minutes to a few hours to
propagate — if the domain is brand new, wait and re-run `docker compose -f
docker-compose.client.yml up -d` (or just `./install.sh` again).

**Is the app healthy?**
```bash
curl -I https://your-domain.com/health
```
A `200 OK` means the API is up and the database is reachable. If it hangs or
errors, check `docker compose -f docker-compose.client.yml ps` for any
service that isn't `healthy`, then check that service's logs.

**I forgot the admin password / need to reset it.**
Edit `.env`, set `SUPERADMIN_PASSWORD` to a new value (16+ characters), then
restart the API:
```bash
docker compose -f docker-compose.client.yml up -d api
```
The password is re-applied to the admin account on every API start — no
database surgery required.

**A service keeps restarting.**
```bash
docker compose -f docker-compose.client.yml logs --tail=200 <service>
```
Common causes: a required `.env` value is missing or a value copied wrong
(check for trailing spaces), or the database hasn't finished starting yet
(the API waits for it, but gives up after a timeout on a very slow disk).
