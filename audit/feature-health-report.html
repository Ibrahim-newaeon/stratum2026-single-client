Executive Summary

29 findings
0 critical · 2 high

The multi-tenant→single-tenant conversion is, at its foundation, clean and well-executed. Runtime verification confirmed login, token refresh, authenticated reads/writes, RBAC enforcement, a fully de-tenanted schema (0 tenant_id columns in-DB), fresh-install migration from zero, and a single global encryption key. The hard failure modes an audit hunts for — cross-tenant data leak, undecryptable secrets, tenant residue in cache/queue/metric keys, silent test-coverage deletion — are all absent. The live defects are concentrated in routing wiring, job-queue binding, and frontend dead-links.

Top 5 risks

5-1

Four owner/admin surfaces return 404 High Broken

Routers double-prefixed (registry prefix stacked on module prefix); the frontend calls the single-prefix path. Platform Analytics, Audit Services, AI Insights, and the Compliance Dashboard are 100% non-functional. Reproduced over live HTTP.

6-1

All scheduled data refresh silently never runs High Broken

Beat jobs route to sync/ml queues that no worker consumes. Hourly campaign sync, daily forecasts, 30-min predictions, and audience auto-sync never execute — the product operates on stale data. Confirmed via Celery import.

11-1

Account pages render fabricated data as real Med Broken

The AM Portfolio / Narrative views fall back to hardcoded sample accounts (fake MRR & plan tiers) instead of erroring when their deleted API 404s.

13-1 / 13-2

Boot & health traps found at runtime Med Broken

The API hard-crashes at startup if superadmin env vars are unset (a SystemExit escapes the best-effort guard); the SPA catch-all shadows /health when the API serves the frontend — a healthcheck-killer for single-container deploys.

3-1

Demoted admins keep power until token expiry Med Degraded

Privileged user-management and console-flag routes trust the stale JWT role, and no token is revoked on demote/deactivate — access persists for up to the access-token lifetime.

Conversion foundation — verified sound

  • Schema de-tenanted — 0 tenant_id columns / 0 tenant_* tables confirmed in-DB
  • Single global encryption key — no lost per-tenant derivation; secrets decrypt
  • Auth core live — login, refresh rotation, 401 guard; JWT carries no tenant claim
  • Fresh install — migrations run from zero cleanly; single head
  • Tests converted, not deleted — 5,700 tests; isolation suites justifiably removed
  • Rate-limit / cache / storage — per-principal, tenant-free keys, symmetric paths

Where the damage is concentrated

  • Routing wiring — 4 double-prefixed routers + 3 orphaned FE→BE contracts
  • Job-queue binding — scheduled sync/forecast/prediction jobs stranded
  • Realtime — built but unwired end-to-end (dashboard polls as fallback)
  • Frontend dead-links — fabricated data, dead nav, broken client switcher
  • Singleton tables — enforcement / onboarding / CRM lack the one-row constraint
  • Boot / health — two runtime-only traps in startup + SPA routing

Assumptions & Limitations

Runtime scope. The app was booted locally against a freshly-migrated scratch DB plus the existing Postgres/Redis containers; core paths were verified live. Not exercised: file upload (see §5), live job execution, full E2E/Playwright, the production Railway environment, and load testing.

Causation. Several BROKEN findings (5-1, 6-1, 13-2) are infrastructure/wiring bugs not strictly caused by the tenant conversion; they are reported because they are live feature-health defects. Findings 2-3 and 6-4 are explicitly pre-existing (noted in-code).

Environment drift observed. Running-container credentials differ from the repo .env; installed fastapi 0.129.0 differs from pinned 0.139.2; host Python 3.12 differs from target 3.11. None blocked the audit, but they indicate config/dependency hygiene worth reconciling.

Confidence labeling. No OPERATIONAL rating rests on "the code looks correct" alone — each cites a phase check, and seven feature groups plus the headline finding are runtime-verified. Low-confidence positives were not marked OPERATIONAL.

Bottom line. The conversion's foundation — schema de-tenanting, encryption, uniqueness, auth, test conversion, migration-from-zero — is genuinely sound. The defects are concentrated in routing wiring, job-queue binding, and frontend dead-links: precisely the surfaces a core-flow smoke test never touches.
