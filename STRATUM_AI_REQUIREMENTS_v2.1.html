Overview

Product & the Trust Gate

Stratum AI is a Revenue Operating System with a Trust-Gated Autopilot. It ingests advertising and customer signals across Meta, Google, TikTok and Snapchat, scores how trustworthy those signals are, and only allows automation (budget shifts, pausing, scaling) to execute when signal health passes safety thresholds. This build is a single-client deployment: one organization, no multi-tenant partitioning, no billing tiers.

Signal Health Check   →   Trust Gate   →   Automation Decision
  [HEALTHY  ≥70]           [PASS]            [EXECUTE]
  [DEGRADED 40–69]         [HOLD]            [ALERT ONLY]
  [UNHEALTHY <40]          [BLOCK]           [MANUAL REQUIRED]

Signal Health is a composite 0–100 score (stratum/core/signal_health.py · HealthConfig):

ComponentWeight
EMQ (Event Match Quality)40%
Freshness25%
Attribution Variance20%
Anomaly15%

When CDP data is available the four base weights scale by 0.9 and a CDP component contributes 10%. The dashboard overview card uses a separate lightweight heuristic (Freshness 40 / EMQ 35 / Connectivity 25) — the two must not be conflated.

Thresholds are org-configurable (TrustGateConfig: pass 70 · hold 40 · high-risk 80 · conservative 60). Hard rule: never auto-execute when signal_health < 70.

Feature 1

01Trust Engine

The decision core. Continuously scores signal reliability per platform and converts the score into a gate decision: PASS (automation may run), HOLD (alert only), BLOCK (manual approval required). Protects ad spend from acting on broken or stale data.

Client provides: nothing beyond connected platforms; thresholds are tunable in Organization settings.

Technical requirements

Key files

analytics/logic/signal_health.py · stratum/core/signal_health.py · stratum/core/trust_gate.py · fact tables in models/trust_layer.py

Requirements

  • Composite weights exactly as the Overview table; weights must always sum to 1.0.
  • No hardcoded thresholds — read from TrustGateConfig.from_org_settings.
  • Daily signal-health rollup (beat 02:00 UTC) populates FactSignalHealthDaily; the gate, dashboard trust layer, and autopilot health check all read this table — without the rollup they see permanent no_data.
  • Attribution-variance rollup at 02:15 UTC populates FactAttributionVarianceDaily.
  • Every gate decision is audit-logged.
Feature 2

02Customer Data Platform (CDP)

Unified customer profiles built from events and identities: identity resolution, behavioral/predictive segments, computed traits, RFM analysis, funnels and consent management. Segments feed Audience Sync and the EMQ signal that drives trust.

Client provides: event streams (web/pixel/webhook/CSV) and consent policy decisions.

Technical requirements

Key files

models/cdp.py · analytics/logic/emq_calculation.py · services/cdp/audience_sync/

Requirements

  • Profiles, identity graph (anonymous→known→customer), segments, computed traits, RFM, lifecycle stages, funnels.
  • EMQ (0–100) measures event-match fidelity per platform and contributes 40% of signal health.
  • PII is Fernet-encrypted at rest; hashed (SHA-256) for platform audience matching.
  • GDPR/CCPA surface: export, erasure, consent — gated by FEATURE_GDPR_COMPLIANCE on.
Feature 3

03Autopilot Enforcement

Executes approved optimization actions (budget, bidding, pause/enable, scaling) — but only through the Trust Gate. Three enforcement modes: Advisory (never executes), Soft-Block (alerts), Hard-Block (manual approval required).

Client provides: chosen enforcement mode + autopilot level (0–2) in settings.

Technical requirements

Key files & tables

autopilot/enforcer.py · autopilot/service.py · tables enforcement_settings, enforcement_rules (renamed from tenant_* in migration b7e3f4a9c2d1)

Requirements

  • Approved actions applied via a 5-minute backstop sweep (schedule_apply_actions_queue) in addition to direct dispatch at approval time.
  • Any bypass flag (skip_gate/force/override) requires admin permission AND emits an audit log.
  • Emergency stop surface in the frontend (components/autopilot/EmergencyStop).
Feature 4

04Campaign Builder

Draft, validate and (behind a flag) publish campaigns to the connected ad platforms. Owns the platform OAuth connection lifecycle: start, refresh, health.

Client provides: platform app credentials (see each platform section) and ad-account IDs.

Technical requirements

Key files

models/campaign_builder.py · api/v1/endpoints/campaign_builder.py

Requirements

  • OAuth start: POST /api/v1/campaign-builder/connect/{platform}/start — client IDs are read from settings (config.py), never raw os.environ; unconfigured platform → 400 with "not configured".
  • Connection state machine: PlatformConnection.status ∈ {connected, expired, error, …}. The source of truth is status == ConnectionStatus.CONNECTED — there is no is_connected column (regression-tested).
  • Publishing gated by ENABLE_CAMPAIGN_PUBLISH off; connector beat tasks (account sync / token refresh / health) gated by ENABLE_CAMPAIGN_BUILDER_BEAT off.
Feature 5

05Audience Sync

Pushes CDP segments to the ad platforms as targeting audiences: Meta Custom Audiences, Google Customer Match, TikTok Custom Audiences, Snapchat Audience Match. PII goes out hashed only.

Client provides: platform connections with audience-write capability (covered by the scopes in each platform section).

Technical requirements

Key files

services/cdp/audience_sync/

  • Auto-sync sweep every 15 min executes due PlatformAudience schedules (auto_sync + next_sync_at <= now, triggered_by="schedule").
  • Emails/phones hashed SHA-256 before leaving the system; raw PII never sent.
Feature 6

06Authentication & Access

JWT-based auth with refresh rotation, TOTP MFA, API keys and full audit trail. Invite-only by default: teammates are added by the owner via invite; open self-registration requires explicitly setting a flag.

Client provides: the initial owner account (seeded superadmin) and team email addresses to invite.

Technical requirements

Key files

auth/ · core/security.py · services/mfa_service.py

  • JWT HS256; access token 30 min, refresh 7 days; Redis blacklist on logout. Token middleware fails open if Redis is down but still rejects non-access token types.
  • POST /auth/register gated by ENABLE_PUBLIC_SIGNUP default off — invite-only; registration requires a one-time email/WhatsApp OTP verification token (Redis-stored, single use).
  • No PII and no tenant claim in JWTs; bcrypt password hashing; secrets module for tokens; hmac.compare_digest for comparisons.
  • Role-based idle timeout 15–60 min with warning; tokens in sessionStorage (never localStorage).
Feature 7

07Analytics & ML

Eight analytics modules (signal health, EMQ, attribution, anomalies, pacing, cohorts, funnels, benchmarks) plus ML predictors: forecasting, budget optimization, churn/LTV, segmentation and model explainability. Attribution supports MTA, Markov and Shapley models.

Technical requirements

Key files

analytics/logic/ (8 modules) · app/ml/

  • ML models are pre-trained at Docker build time (multi-GB runtime training is forbidden); ML_AUTO_TRAIN self-heals a fresh deploy but must be off in CI/health-probe environments.
  • Provider switch ML_PROVIDER=local|vertex (Vertex needs GOOGLE_CLOUD_PROJECT/VERTEX_AI_ENDPOINT/GOOGLE_APPLICATION_CREDENTIALS).
  • Daily forecasts 06:00 UTC · fatigue scores 03:00 · daily scores 04:00 · live predictions every 30 min.
  • Copilot default is a deterministic keyword classifier; Anthropic generation (COPILOT_LLM_ENABLED + ANTHROPIC_API_KEY) and pgvector RAG (COPILOT_RAG_ENABLED + OPENAI_API_KEY) are opt-in.
Feature 8

08Integrations Hub

Central OAuth + adapter layer for the four ad platforms, with a sync orchestrator that pulls campaigns and metrics on schedule. Adapter registry pattern makes adding a platform a 5-step recipe.

Technical requirements

Key files

services/oauth/ (factory + per-platform) · app/stratum/adapters/ + registry · services/sync/orchestrator.py

  • USE_MOCK_AD_DATA=true serves deterministic mock data for development; production runs with it false.
  • New integrations follow .claude/skills/add-platform-integration (OAuth → collector → health wiring → registry → docs).

Delivery

Frontend

React 18 + Vite + TypeScript. Four shells: Dashboard (~60 routes), owner Console, CMS and client Portal, plus the public marketing site (English + Arabic RTL). Design system: "Bloomberg density · Apple restraint · ember warmth" — dual dark/light themes, semantic tokens, primitive component library.

Technical requirements
  • Semantic Tailwind tokens only (bg-card, text-foreground, text-muted-foreground, border-border) — no raw text-gray-* (swept 2026-07-15; one intentional brand-gradient exception).
  • Fonts: Geist + Geist Mono in the app shell; Cairo is loaded by the static Arabic landing asset only.
  • Env: VITE_API_URL (includes /api/v1 — the only API-URL name the code reads), VITE_WS_URL (includes /ws), VITE_SENTRY_DSN, VITE_SENTRY_DEBUG, VITE_ENABLE_DEMO_MODE. Vite bakes these at build time.
  • Auth session restored from localStorage['stratum_auth']; access token in sessionStorage with in-memory cache + 401 refresh mutex.
  • Legacy redirects: /overview→/dashboard/overview, /dashboard/superadmin/*→/console/*, /app/:tenantId/*→/dashboard/*, am/tenant/:id→am/account/:id.
  • Tests: vitest (jsdom, ratcheted coverage) + Playwright across 5 projects (Chromium/Firefox/WebKit/Mobile Chrome/Mobile Safari) — specs: auth, dashboard, emq, logout, mobile, onboarding, settings, signup-otp, whatsapp, console.

Infrastructure & Ops

Docker Compose for local (7 services), Railway for production (Postgres, Redis, api, worker, beat, frontend; push-to-main auto-deploys). CI enforces quality gates, tests, security scans and a removed-scope residue gate.

Technical requirements

CI gates (ci.yml)

  • backend-quality (Ruff/Black/isort/mypy, aggregated so no gate masks another) · backend-tests (unit+integration on pgvector+redis) · backend-security (Bandit, pip-audit) · frontend (audit, lint, tsc, vitest, build) · e2e (Playwright/chromium on PRs) · Trivy · gitleaks · release gate · k6 smoke.

  • Residue gate: git grep -iE 'tenant_id|X-Tenant-ID|stripe' over source must return empty (documented narrow exclusions only).

Acceptance criteria

The release gate: all of the following hold before shipping.

Checklist (spec §10)
  • Trust Gate: no automation executes below signal-health 70; enforcement modes honored; every decision audit-logged.
  • API contract: OpenAPI docs gated by DOCS_API_KEY in prod; every mutating endpoint has auth + schema + audit + rate limit; flagged-off routers return 404/403 per flag semantics; knowledge graph returns 503 (not crash) without Apache AGE.
  • Coverage: combined unit+integration meets the .coveragerc ratchet (only ever raised; 74.0 at revision time); core/autopilot/analytics trend toward 90%.
  • CI: all jobs green including residue gate, security scans and the vacuous-pass floor guard.
  • Ops: Prometheus scrapes bearer-gated /metrics; Sentry receives errors; images build; Railway probes pass.
  • Security: invite-only signup default; PII Fernet-encrypted; no PII in JWTs; webhook signatures verified; secrets never committed.
